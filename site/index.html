The problem

The network spreadsheet is always wrong.

Most IT teams track VPCs and subnets by hand: a shared sheet, a wiki page, a CMDB export. It goes stale on the first day, and the gaps show up at the worst possible moment.

Drift

Subnets are created by Terraform, consoles and scripts. Nobody updates the sheet, so it slowly turns into fiction.

Overlaps found too late

Two teams pick the same CIDR in different accounts. You find out when peering or Transit Gateway routing breaks.

No owner, no headroom

Who owns this subnet? Is it 90% full? Answering takes a ticket, three consoles and a guess.

And every tool that promises to fix this starts with "first, tag everything" — which is why the spreadsheet is still there.

The product

A minimal core that does one job well. Automation when you want it.

The inventory is useful on its own and safe to run anywhere: it only reads. Automatic management is a separate, opt-in layer on top of the same API.

CORE · READ-ONLY

Live network inventory

Everything the spreadsheet tried to be, generated from the cloud and kept current.

  • Discovers VPCs by tag across accounts and regions, including every subnet inside them
  • CIDR, AZ, free IPs, utilization, public/private, owner, environment, tier
  • Finds missing required tags and CIDR overlaps between VPCs, even across accounts
  • Shows what is not managed yet and takes it under management in one step: a ResourceImport tags the resource in AWS, nothing else
  • Updates within seconds from CloudTrail events, with a periodic full resync as a safety net
  • Prometheus metrics, kubectl, and a read-only Google Sheet mirror for people who still want a table
Only ec2:Describe* calls. Nothing in your cloud is ever modified. The Google Sheet mirror is written, never read back, so the old spreadsheet stops being something anyone maintains.
OPTIONAL · AUTOMATIC MANAGEMENT · v0.3.0

Subnets on demand

Teams ask for capacity; the operator picks a free CIDR and creates correctly tagged subnets.

  • SubnetClaim: size, tier, AZ spread and target VPC selector
  • CIDR allocation from Amazon VPC IPAM pools or a built-in allocator over tagged pools
  • Route-table association and the tags ELB and Karpenter already select on
  • "Allocate only" mode for Terraform-first teams: the CIDR is reserved, Terraform creates the subnet
  • Never deletes subnets and never touches Terraform-owned resources
Shipped behind --enable-writes and a write role of its own: subnets on demand in v0.2.0, ResourceImport and the auto-import policy in v0.3.0. Tagging a resource needs nothing but ec2:CreateTags.
How it works

One operator, every account, near real time.

The operator runs in a hub cluster and reaches spoke accounts with short-lived AssumeRole credentials. Change events tell it which account and region to look at again.

01

Tag, or import

Mark VPCs with hs/managed=true and owners — by hand, in Terraform, or by importing what discovery found untagged. Tag policies keep the schema honest.

02

Scope

A NetworkScope lists accounts, regions and required tags.

03

Discover

The operator assumes a read-only role per account and mirrors what it finds.

04

React

CloudTrail events trigger a targeted resync of just the account/region that changed.

Onboarding

From untagged to managed in one step.

Discovery does not stop at the tag selector: it lists what it can see but nobody has claimed. Importing a resource applies the organization's tags in AWS — nothing else changes — and the inventory picks it up on the next CloudTrail event. Shipped in v0.3.0, by hand or by policy.

Nothing stays hidden

Every VPC and subnet in the accounts is discovered; the tag selector decides what is managed, not what is visible.

An import is a tag change

A ResourceImport object, applied by hand or through GitOps, becomes one ec2:CreateTags call. Tags stay the source of truth; the CRD is not a second spreadsheet.

Terraform-aware

Resources that carry managed-by=terraform get a warning and the ignore_changes snippet, so the next plan does not undo the import.

Narrow permissions, full audit

The write role for imports holds ec2:CreateTags and nothing else; who imported what, and when, is in the object and in CloudTrail.

Automatic mode · v0.3.0

Or let policy do the importing.

Someone creates a subnet from the console at 5 pm on a Friday. The CloudTrail event that tells the operator about it also says who did it. With an auto-import policy on the scope, the operator derives the tags — from the creator's role, from the parent VPC, or from the account's defaults — and applies them within seconds. What it cannot resolve becomes an alert for a human instead of a silent gap.

  • Three sources for the owner, tried in order: the creating principal, the VPC the subnet lives in, the account's default
  • Skip rules for Terraform: by tag or by the principal that created it, so pipelines keep their own state clean
  • Dry run first. The operator still creates the ResourceImport objects — you review a day of them before switching to Apply
  • Nothing owner-less is tagged. If no rule yields an owner, the resource stays unmanaged and the alert fires
networkscope.yamlauto-import policy
spec:
  autoImport:
    mode: DryRun                  # DryRun | Apply
    fromCreator:
      - principal: "arn:aws:sts::*:assumed-role/payments-*"
        tags: { hs/owner: team-payments }
      - principal: "arn:aws:sts::*:assumed-role/data-platform-*"
        tags: { hs/owner: team-data }
    inheritFromVPC: [hs/owner, hs/env]
    accountDefaults:
      - account: "333333333333"
        tags: { hs/env: prod }
    skip:
      - tag: managed-by=terraform
      - principal: "arn:aws:sts::*:assumed-role/terraform-*"
    requireTags: [hs/owner]      # otherwise: leave unmanaged, alert

Features

Built like a cloud-native component, not a script.

Tag-driven discovery

Select VPCs by tags; every subnet inside is included, so untagged ones cannot hide.

Hub and spoke

One operator, many accounts. Role ARNs are checked against the declared account ID.

Event-driven

EventBridge → SQS, debounced, leader-only. Only the changed account/region is resynced.

Compliance findings

Missing required tags per subnet, surfaced in status and as metrics.

Overlap detection

CIDR overlaps across VPCs and accounts, before peering or TGW routing fails.

Prometheus metrics

Free and total IPs, missing tags, overlaps, target health. Alert on 80% before it is 100%.

Terraform-friendly

Terraform-owned resources are observed, never mutated. Allocate-only mode keeps Terraform in charge.

One-step onboarding

Untagged VPCs and subnets are listed, not hidden. Importing one applies the tags in AWS — with a warning when Terraform owns it.

Safety

Designed so you can install it on day one.

Read-only by default

The core uses three EC2 Describe calls. Write permissions live in a separate role you add later, if ever.

Never deletes cloud resources

Removing an object from the cluster never removes a subnet. Deletion stays a human decision.

Right account or nothing

Credentials are verified against the declared account ID, so a typo cannot report another account's networks.

Degrades gracefully

An unreachable account is reported, not erased. Its last known state stays until it syncs again.

Clouds

AWS first. Vendor-neutral by design.

Discovery sits behind a cloud-neutral inventory model. Each provider keeps its own API group, so the model follows real platforms instead of a lowest common denominator.

Amazon Web Services

aws.hypersurgery

VPCs, subnets, route tables, CloudTrail events, AssumeRole. Available now.

Google Cloud

Regional subnetworks, shared VPC host projects, Cloud Asset feeds. Planned.
