{{- if .Values.leaderElection.enabled }}

Replicas: {{ .Values.replicaCount }}. One of them holds the leader election lease and does
all the work; the rest sit on the lease and take over when the leader's pod goes away. A leader
that is stopped — a drain, a rollout — finishes its in-flight work and hands the lease over on
the way out, so a standby takes over within a few seconds. A leader that crashes cannot hand
anything over, and its lease runs out after {{ .Values.leaderElection.leaseDuration }}. A sync interrupted
halfway is redone by the next leader: a scope's lastSyncTime only advances once the sync has
finished, so the status is never left half-written.
{{- if lt (int .Values.replicaCount) 2 }}

  With replicaCount: 1 there is nothing to take over. Set replicaCount: 2 for that.
{{- end }}
{{- if and .Values.podDisruptionBudget.enabled (lt (int .Values.replicaCount) 2) }}

  No PodDisruptionBudget was created: over a single replica it would block node drains
  instead of surviving them.
{{- end }}
{{- else }}

Leader election is off, so run a single replica: two would reconcile the same scopes at
the same time.
{{- end }}

The admission webhooks are on: an invalid SubnetClaim, NetworkScope or ResourceImport is
refused by kubectl instead of failing later in a status.

and upgrade with the new webhook.certificate.caBundle when its CA changes.
{{- else if eq (include "subnet-operator.webhook.certManager" .) "true" }}
cert-manager issues the serving certificate.
{{- else }}
The serving certificate is signed by the chart for {{ .Values.webhook.certificate.duration }} and renewed only by a helm
upgrade in the last {{ .Values.webhook.certificate.renewBefore }} before it expires; without one the webhooks refuse every
write once it has. Installing cert-manager and upgrading hands the certificate over to it,
which renews it on its own.
